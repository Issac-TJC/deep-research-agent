# V1 实施计划

先完成交付契约，再整理面试深挖材料

## 1. 实施优先级

在 `research-blueprint-v1` 分支实现蓝图第 1.3 节的完整 V1，保留现有文档修改。

执行顺序固定为：

1. 完成研究能力、四类 Agent、证据链、运行可靠性、多租户隔离、工作台和评测工具。
2. 开发过程中同步记录实际问题、排查过程、解决方案和验证结果。
3. 功能完成后，结合代码、开发日志和实验结果整理面试深挖文档。

功能实现不以“已经发生对应故障”或“已经证明性能收益”为前置条件。基线和观测能力随开发建立，对照实验集中在完整闭环形成后进行。

知识库检索方案选型作为主验收案例；技术比较、论文／实验报告研读和通用研究均按 V1 契约交付。

## 2. 功能与架构

**统一研究引擎**

- 实现 Planner、Researcher、Reviewer、Writer 四类 Agent；角色分别负责规划、研究、审查、写作与局部修订。
- Researcher 使用独立上下文和有界工具循环；Reviewer 提出补证建议，由确定性调度器执行资源与权限检查。
- 三个模板共用研究引擎，通过 brief、来源偏好、审查标准和报告结构体现差异。
- 技术比较输出比较矩阵、适用条件、推荐依据、反证和未知项。
- 论文研读重点输出问题与贡献、方法原理、实现流程、实验设计、结果解释、局限与研究建议，同时保留证据支持检查。区分作者陈述、系统推断和待验证假设；相关文献默认最多补充 3 个来源。
- 保持研读边界，不执行论文代码、不声称复现论文实验。

**模型与参考实现**

- 首先实现 `DeepSeekProvider`，经统一 `ModelProvider` 接口调用；模型、端点、参数和密钥通过配置管理，后续供应商通过适配器扩展。
- 默认使用 `deepseek-flash`、thinking low 建立统一基线；保存模型配置、调用用量和供应商协议需要的消息字段。
- 工具调用和结构化输出进行 schema 校验，处理空响应、截断、非法参数、超时和有限重试。
- 默认搜索适配器使用 Tavily；搜索摘要用于发现来源，报告事实引用实际获取的原文。
- 吸收 HelloAgents 第 14 章的任务组织和过程展示，以及 DeerFlow 的容量控制、上下文管理、结果验收与事件机制；参考仓库不作为运行依赖。

**运行与证据架构**

- 使用 FastAPI、单进程 LangGraph Worker、PostgreSQL、MinIO 和 Next.js/TypeScript，通过 Docker Compose 运行。
- 实现 HTML、文本型 PDF、Markdown 的获取、解析、版本保存和证据定位；PDF 支持页码及可提取的位置，解析失败明确展示。
- 完整来源保存为工件；`ContextBuilder` 装配 brief、用户约束、任务状态、精选证据和必要工具历史，支持按需回读原文。
- 报告采用带稳定节点 ID 的结构，修订生成不可变版本；引用绑定来源版本和 evidence span。
- API、CLI 和评测入口共用 `ResearchService`，领域契约与具体 SDK 解耦。

## 3. 公共接口与工程保障

**接口与类型**

实现运行创建／列表／详情、上传、取消／恢复、来源／证据读取、报告导出及 SSE 回放接口。创建运行支持幂等，事件支持断线补读和客户端去重。

实现蓝图中的 brief、任务、来源、claim、evidence span、审查结果、报告、研究包和事件契约；补充论文理解、研究建议、模型用量、上下文快照及评测结果类型。执行状态、停止原因和质量状态分别保存。

**可靠性与预算**

- PostgreSQL 持久化运行队列、租约、父／子图 checkpoint 和事件；fencing token 同时保护业务结果及 checkpoint 写入。
- 恢复复用已提交产物，保持预算累计；取消先持久化，再停止派发并拒绝迟到提交。
- 默认单个活跃 run、最多 3 个 Researcher 并发、累计 8 个研究任务、2 轮补证和 2 轮局部修订。
- 开发 profile 限制为 12 次搜索、80 次工具调用、40 次模型调用、累计 250k token、20 分钟和每 run 2 美元；最多重试 2 次，重试计入额度，等待队列最多 10 个运行。
- 调用前原子预留预算，调用后结算；未知费用保留预留。为写作和验证保留 20% 额度，达到限制时输出部分研究包与未解决项。

**隔离与工作台**

- 两个测试租户覆盖 API、RLS、checkpoint、文件、证据、缓存和事件授权。
- 实现抓取 SSRF 防护、受限解析和安全内容渲染。
- 工作台展示研究计划、任务进度、来源原文、引用定位、报告、论文研究建议、未解决项和运行成本。
- 保留完整版本与调用计量；应用侧上下文筛选和 DeepSeek 服务端缓存分别记录。

## 4. 开发顺序与文档

| 阶段 | 交付内容 |
|---|---|
| 1：基础闭环 | 工程骨架、契约、数据库迁移、DeepSeek 接入、调用计量、单 Researcher 基线 |
| 2：研究与证据 | 搜索／抓取／解析、来源版本、claim／span、三个模板、结构化研究包 |
| 3：完整多 Agent | 四角色、任务依赖、补证、局部修订、上下文管理、checkpoint、预算与取消 |
| 4：产品与隔离 | Web 工作台、证据定位、事件回放、两租户隔离、故障与安全验证 |
| 5：评测与展示 | 基线／消融实验、问题修复、三段演示、运行说明和面试深挖文档 |

从第一阶段维护 `docs/development-log.md`，记录实际现象、复现条件、相关版本／run／trace、排查证据、根因、方案取舍、修复与复测结果。实际问题、故障注入和待验证风险分别标注；尚未解决的问题保留状态。

完成主要功能后编写 `docs/interview-deep-dive.md`，解释架构取舍、多 Agent 分工、上下文策略、工具遗漏定位、错误决策检查、恢复与幂等、成本与耗时、项目差异和剩余不足。区分原始设计依据、开发中发现的问题以及事后实验结论。

## 5. 验收与实验

- 建立 20 个开发 briefs 和 10 个保留 briefs，覆盖三个模板；保留集不参与提示词调优。
- 验证完整研究闭环、原文追溯、论文解释与研究建议，以及证据不足时的明确披露。
- 使用真实 PostgreSQL／MinIO 验证 Worker 中断恢复、预算竞争、取消迟到写入、SSE 重连和跨租户访问。
- 覆盖超时／429、非法 JSON、遗漏或错误工具调用、解析失败、上下文信息丢失、提示注入、SSRF 和前端内容安全。
- 对比单 Researcher、多 Researcher 无全局补证、完整系统；消融并发度和上下文策略，固定模型、来源和总预算。
- 记录质量、覆盖、token、工具调用、重试、成本、耗时、缓存命中及上下文信息保留情况；报告样本量和实验限制。
- 初次真实 API 联调与验收总预算不超过 10 美元。完整评测工具与数据集照常交付，尚未执行的付费实验明确标记。
- 交付技术选型、论文理解与研究启发、Worker 中断恢复三段可复核演示。README 与面试材料仅引用实际实现和测量结果。
